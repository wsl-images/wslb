# WSLB

`wslb` builds and manages WSL images from a `devcontainer.json/jsonc` superset.

[![Compatibility Matrix](https://github.com/wsl-images/wslb/actions/workflows/compatibility-matrix.yml/badge.svg?branch=main)](https://github.com/wsl-images/wslb/actions/workflows/compatibility-matrix.yml)
[![CI](https://github.com/wsl-images/wslb/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/wsl-images/wslb/actions/workflows/ci.yml)
[![Release Pipeline](https://github.com/wsl-images/wslb/actions/workflows/ci-cd-workflow.yml/badge.svg)](https://github.com/wsl-images/wslb/actions/workflows/ci-cd-workflow.yml)

It keeps legacy commands (`build`, `install`, `ls/list`, `status`, `stop`, `shutdown`, `rm`, `version`) and adds workspace + managed lifecycle APIs.

## Quick Start

```bash
go build -o wslb.exe .
./wslb.exe workspace init
./wslb.exe workspace validate --json
./wslb.exe workspace plan --all --json
```

You can also use a `devcontainer` superset with a top-level `wslb` block (`.json` or `.jsonc`):

```bash
./wslb.exe workspace validate --workspace-file .devcontainer/devcontainer.json --json
./wslb.exe wsl --workspace-file .devcontainer/devcontainer.json install <imageId>
```

The `wslb` superset supports full `wsl.conf` sections, optional host `.wslconfig` management (`wslb.wslconfig`), and `/etc/wsl-distribution.conf` settings (`oobe`, shortcut/icon, `windowsterminal`/`windowsTerminal`, profile templates), including `simpleIcon` slugs from Simple Icons.
Schema URL for editor association:
- `https://raw.githubusercontent.com/wsl-images/wslb/main/schemas/wslb-workspace.schema.json`

## New Commands

- `wslb workspace init|validate|plan|build|publish`
- `wslb doctor`
- `wslb catalog feature describe <ref>`
- `wslb wsl state create|install|upgrade|rollback|status <imageId>`

All major new commands support `--json`; long-running commands optionally emit `--ndjson`.

## WSLB Store UI (Local)

`wslb` now includes a local Store-style UI for managing multiple distro profiles and devcontainer manifests:

```bash
npm run store
```

Open `http://127.0.0.1:4893`

- WSL images OOBE matrix:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/oobe-matrix.ps1 -Out .\wsl-images-oobe-matrix-report.json
```

- Base distro matrix (25 official base images):

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/base-image-matrix.ps1 -Out .\base-image-matrix-report.json
```

GitHub Actions runs these matrix checks in the `Compatibility Matrix` workflow and auto-refreshes the compatibility section in this README.

## WSL Stuck Recovery

If WSL commands hang, run:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/wsl-recover.ps1
```

If that is not enough, run elevated:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/wsl-recover.ps1 -Deep
```

Or auto-elevate:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/wsl-recover.ps1 -Deep -AutoElevate
```
